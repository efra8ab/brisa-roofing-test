# AGENTS.md

Context for AI agents working in this folder. Keep it current: when you learn something about the project, add it here.

## What this is

A technical test. The person you're working with is a job candidate. `START_HERE.md` has the task, the rules and the deliverables. Read it first.

The candidate makes the decisions and must be able to explain every change on video. Help them investigate, explain what you find, and don't make big changes without telling them.

## The client

Brisa Roofing, a roofing company in Miami, FL (Eastern Time). Contact: Carmen.

How a lead flows:

1. A visitor fills in the form on the landing page (`site/`, Next.js, hosted on Vercel).
2. The form posts to `/api/lead`, which validates it and forwards it to a Make webhook.
3. The Make scenario (`make/scenario-blueprint.json`) adds a row to a Google Sheet and emails Carmen a "New lead" notification.
4. Every morning we run `reports/daily_report.py` on the sheet export and email Carmen the output.

The domain `brisaroofing.com` is registered at Hostinger. DNS and email are on Hostinger.

## Commands

```bash
python3 tools/mock_make_webhook.py          # fake Make webhook
cd site && npm install && npm run dev       # website on http://localhost:3000
python3 reports/daily_report.py             # daily report
python3 -m unittest discover -s reports -v  # report tests
```

## Rules

- Never edit `data/`, `dns/` or `make/`. They are evidence. For changes in the client's Hostinger, Make or Vercel accounts, write the exact change in `FINDINGS.md` instead.
- Investigate before changing code. Back every finding with evidence: a file and line, a log line, a row in the data.
- Don't say something is fixed until you've run it and seen the result.
- If you're not sure, say so. Never invent findings.
- After each meaningful step, add a short entry to `JOURNAL.md`: time, what was done, what was learned.
- `site/AGENTS.md` and `site/CLAUDE.md` are generated by Next.js (`next dev` re-creates them). They point to the Next.js docs in `node_modules/next/dist/docs/`. Leave them as they are.
